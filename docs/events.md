# Формат событий: пункт 3.1

Событие — пока только данные в `src/content/events.ts`. Общие типы и `validateEvents` находятся в `src/game/events.ts`; примеры и их числовые последствия черновые. События не выбираются, не показываются и не изменяют игру.

У события есть постоянный уникальный `id` (латинские строчные буквы, цифры и дефисы), `title`, `text`, непустой список реплик `dialogue` с полями `speaker` и `text`, `trigger`, список условий `conditions`, признак повторяемости `repeat` и непустой список `choices`. Идентификаторы вариантов уникальны в рамках одного события. Не меняйте опубликованный идентификатор без отдельного решения о совместимости.

`trigger` описывает возможный момент: `{ type: 'after_action', action: 'work' }` (также `eat`, `rest`) или `{ type: 'state' }`. Условия — список границ `{ field, min?, max? }`, где можно указать одну или обе включительные границы. Все условия списка предполагается выполнять одновременно; пустой список не ограничивает показ. Доступны `day`, `actionsRemaining`, `energy`, `satiety`, `sanity`, `money`, `motivation`, `unfinishedProjects`. Условия выбора имеют тот же формат и необязательны.

Вариант содержит `id`, текст `text`, объект числовых изменений `effects` и видимый после выбора текст `result`. Последствия могут описывать изменения энергии, сытости, кукухи, денег, мотивации и числа проектов; пустой объект означает отсутствие изменений. Отрицательное число — уменьшение. Правила применения, границы при изменениях и недоступность выбора при нехватке ресурсов предстоит реализовать отдельно.

Пример добавления истории в массив `exampleEvents`:

```ts
{
  id: 'quiet-pause',
  title: 'Тихая пауза',
  text: 'На столе нашлось свободное место для чашки.',
  dialogue: [{ speaker: 'Маша', text: 'Пожалуй, это знак.' }],
  trigger: { type: 'state' },
  conditions: [{ field: 'energy', max: 30 }],
  repeat: 'repeatable',
  choices: [{ id: 'pause', text: 'Передохнуть', effects: { sanity: 3 }, result: 'Стало немного спокойнее.' }],
}
```

TypeScript проверяет структуру, допустимые имена полей и варианты триггеров при написании типизированного контента. `validateEvents` дополнительно проверяет непустые тексты и списки, формат и уникальность идентификаторов, допустимость условий, границы и конечность чисел, целочисленность дня, действий и проектов и корректность последствий. Vitest проверяет примеры и случаи ошибок; проверка не запускается автоматически внутри игры.

Открытые вопросы: как часто предлагать повторяемые события, что считать уникальным прохождением и когда сбрасывать его историю; как обозначать и выбирать продолжения историй; какие просмотренные события, выбранные варианты и этапы цепочек сохранять и как обновлять формат сохранения. Связи и прогресс цепочек в состоянии игры пока не добавлены.
