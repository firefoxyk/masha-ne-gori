# Технологии

## Что уже есть

Проект — веб-приложение на React, TypeScript, Vite и CSS с npm и Git/GitHub. Зависимости и точные установленные версии фиксируются в `package-lock.json`; диапазоны указаны в `package.json`. На момент подготовки документации в lock-файле React 19.3.1, TypeScript 7.0.2 и Vite 8.3.8. Инструкции и требования к Node.js и npm находятся в [README](../README.md). TypeScript и production-сборка проверялись командой `npm run build`.

Сейчас реализованы экран прототипа, модель состояния, три основных действия, предупреждения о тяжёлом состоянии, итоги и переходы между днями. Прогресс сохраняется в `localStorage` текущего браузера на устройстве; при очистке данных он может исчезнуть. PWA, публикация, синхронизация и Android-приложение отсутствуют. Vitest проверяет модель, действия, предупреждения, игровой день и сохранение, а Playwright — экран и взаимодействия в Chromium на узкой и широкой области просмотра. Команды и установка браузера описаны в [README](../README.md).

## Рекомендации из исходного материала

- Первая игровая версия — по ссылке, с адаптацией под вертикальный экран Android. Позже предлагается рассмотреть PWA для установки и офлайн-работы; для последней нужно отдельно настроить кэширование и проверить его на устройстве.
- Исходный материал предлагал IndexedDB. Для текущего прототипа выбрано простое сохранение в localStorage с версией формата; экспорт, импорт и миграция пока не реализованы. Локальные данные могут потеряться при очистке браузера или смене устройства и не равны облачной копии.
- Для первой версии предложено хранить игровой контент в JSON или TypeScript, использовать сценарного игрового агента и обойтись без сервера, аккаунтов и реального ИИ API. Это рекомендации, не реализованные решения.
- GitHub Pages предложен как один из вариантов публикации. Capacitor и Android Studio можно рассмотреть позднее для Android-приложения; перенос сохранений между браузером и приложением потребует отдельной проверки.
- Для сцены предложены отдельные изображения комнаты, Маши, гуся и мебели, с простыми CSS-движениями. Формат PNG или WebP и визуальный стиль предстоит проверить.

Нужно выбрать способ размещения, формат контента, дальнейшее развитие сохранений, сроки PWA и офлайн-режима, подход к Android-сборке и формат графики. Пользователь проверила открытие прототипа, действия, предупреждение, переход дня и сохранение после обновления на настоящем Android; детали — в [плане](plan.md). Отдельные сценарии, включая системные панели, сворачивание, офлайн-работу и расход ресурсов, ещё предстоит оценить. Дополнительные детали — в [источнике](sources/Masha_ne_gori_materialy_dlya_Codex.md) и [открытых вопросах](decisions.md).
