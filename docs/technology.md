# Технологии

## Что уже есть

Проект — веб-приложение на React, TypeScript, Vite и CSS с npm и Git/GitHub. Зависимости и точные установленные версии фиксируются в `package-lock.json`; диапазоны указаны в `package.json`. На момент подготовки документации в lock-файле React 19.3.1, TypeScript 7.0.2 и Vite 8.3.8. Инструкции и требования к Node.js и npm находятся в [README](../README.md). TypeScript и production-сборка проверялись командой `npm run build`.

Сейчас реализованы экран прототипа, модель состояния, три основных действия, предупреждения о тяжёлом состоянии, итоги и переходы между днями. Сохранения, PWA, публикация и Android-приложение отсутствуют. Vitest проверяет модель, действия, предупреждения и игровой день, а Playwright — экран и взаимодействия в Chromium на узкой и широкой области просмотра. Команды и установка браузера описаны в [README](../README.md).

## Рекомендации из исходного материала

- Первая игровая версия — по ссылке, с адаптацией под вертикальный экран Android. Позже предлагается рассмотреть PWA для установки и офлайн-работы; для последней нужно отдельно настроить кэширование и проверить его на устройстве.
- Для локальных сохранений предложен IndexedDB: автосохранение после значимых действий, версия формата, проверка повреждённых данных и подтверждение сброса; экспорт и импорт — желательны. Локальные данные могут потеряться при очистке браузера или смене устройства и не равны облачной копии.
- Для первой версии предложено хранить игровой контент в JSON или TypeScript, использовать сценарного игрового агента и обойтись без сервера, аккаунтов и реального ИИ API. Это рекомендации, не реализованные решения.
- GitHub Pages предложен как один из вариантов публикации. Capacitor и Android Studio можно рассмотреть позднее для Android-приложения; перенос сохранений между браузером и приложением потребует отдельной проверки.
- Для сцены предложены отдельные изображения комнаты, Маши, гуся и мебели, с простыми CSS-движениями. Формат PNG или WebP и визуальный стиль предстоит проверить.

Нужно выбрать способ размещения, формат контента, реализацию сохранений, сроки PWA и офлайн-режима, подход к Android-сборке и формат графики. Проверка на реальном телефоне остаётся необходимой: управление, читаемость, системные панели, сворачивание, сохранение, офлайн-работу и расход ресурсов ещё предстоит оценить.
